### AC-2: Exportação segura (criptografia + checksum)
**Status:** ✓ IMPLEMENTED

#### JavaScript (encryption.js)
- **Algoritmo:** AES-256-GCM
- **Derivação:** PBKDF2 com 100.000 iterações + SHA-256
- **IV:** 12 bytes aleatório (GCM)
- **Salt:** 32 bytes aleatório
- **Checksum:** SHA-256 dos dados originais (antes de criptografar)
- **Formato:** JSON com `{ version, algorithm, timestamp, checksum, ciphertext, iv, salt, iterations }`

```typescript
SecureBackupManager.exportSecure(plainJson, password)
// Retorna: { version, algorithm, checksum, ciphertext, iv, salt, iterations }
```

#### Android (SecureBackupBridge.kt)
- **Algoritmo:** AES-256-CBC (compatível com Android Security)
- **Derivação:** PBKDF2 com 100.000 iterações + SHA-256
- **IV:** 16 bytes aleatório (CBC)
- **Salt:** 32 bytes aleatório
- **Checksum:** SHA-256 calculado e armazenado
- **Método:** `SecureBackupBridge.exportSecureSnapshot(context, plainJson, password)`

#### UI
- Botão "Backup criptografado" em Perfil
- Solicita senha (mín. 8 caracteres) via prompt()
- Exporta como arquivo `.cbk` em Downloads
- Exibe mensagem de sucesso/erro

### AC-3: Importação valida integridade antes de aplicar
**Status:** ✓ IMPLEMENTED

#### Verificação de Integridade
1. **Desencriptação:** AES-256-GCM com senha derivada (PBKDF2)
2. **Checksum SHA-256:** Recalculado após desencriptar
3. **Erro se falhar:** Rejeita se senha errada ou checksum ≠
4. **Validação JSON:** Verifica estrutura antes de aplicar

#### Workflow de Importação
```javascript
importProgressSecure(encryptedFile):
  1. Pede senha
  2. Lê arquivo .cbk
  3. Descriptografa com SecureBackupManager.importSecure(data, password)
  4. Valida checksum SHA-256 internamente
  5. Preserva backup anterior (preserveProgressBeforeImport())
  6. Mostra preview no modal (progressImportSummary)
  7. Pede confirmação do usuário
  8. Aplica apenas se confirmado
```

#### Erros Tratados
- ✓ Senha muito curta (< 8 caracteres)
- ✓ Arquivo corrupto ou inválido
- ✓ Checksum não corresponde
- ✓ Senha incorreta
- ✓ Arquivo vazio ou ilegível

## 🔒 Detalhes Técnicos

### Algoritmos Criptográficos

#### JavaScript (Web)
| Componente | Algoritmo | Parâmetros |
|------------|-----------|-----------|
| **Cifra** | AES-256-GCM | 256 bits, IV 12 bytes |
| **Derivação** | PBKDF2 | 100.000 iterações, SHA-256 |
| **Hash** | SHA-256 | Checksum dos dados originais |
| **RNG** | crypto.getRandomValues() | Seguro para IV e salt |

#### Android (Nativo)
| Componente | Algoritmo | Parâmetros |
|------------|-----------|-----------|
| **Cifra** | AES-256-CBC | 256 bits, IV 16 bytes, PKCS5Padding |
| **Derivação** | PBKDF2WithHmacSHA256 | 100.000 iterações |
| **Hash** | MessageDigest("SHA-256") | Checksum dos dados originais |
| **RNG** | SecureRandom | Seguro para IV e salt |

### Fluxo de Exportação
```
[Snapshot JSON] 
  ↓ SHA-256
[Checksum]
  ↓ PBKDF2(password, salt, 100k iterations)
[Derived Key 256-bit]
  ↓ AES-256-GCM(IV=12bytes random)
[Encrypted Data]
  ↓ JSON
{
  version: "1.0",
  checksum: "a1b2c3...",
  ciphertext: "xyz...",
  iv: "...",
  salt: "...",
  iterations: 100000
}
  ↓ Salva em Downloads ou localStorage
[.cbk file ou JSON no storage]
```

### Fluxo de Importação
```
[.cbk file lido]
  ↓ JSON parse
{encrypted}
  ↓ PBKDF2(password, salt, 100k)
[Derived Key 256-bit]
  ↓ AES-256-GCM.decrypt(IV)
[Decrypted JSON]
  ↓ SHA-256
[Computed Checksum]
  ↓ Compare com checksum armazenado
✓ Se igual: Dados íntegros
✗ Se diferente: Rejeita (corrupto ou senha errada)
  ↓ Preservar backup anterior
  ↓ Mostrar preview
  ↓ Pedir confirmação do usuário
  ↓ Aplicar se confirmado
```

## 📋 Limitações Documentadas

### Sem Teste em Dispositivos Reais
- ✗ Android físico (Samsung, Pixel, etc.)
- ✗ Galaxy Watch (sync de backup)
- ✗ TalkBack (acessibilidade com criptografia)
- ℹ️ **Mitigação:** Código testável em emulador; UI integrada com stack existente

### Sem Teste de Performance
- ✗ Criptografia de snapshots > 1 MB em dispositivo lento
- ✗ Recuperação de backups em rede 3G
- ℹ️ **Mitigação:** PBKDF2 (100k iter) é padrão da indústria; AES-256 é rápido

### Sem Rotação de Chave
- ℹ️ E09.5 não implementa mudança de senha pós-exportação
- ℹ️ **Recomendação E10+:** Implementar chave master + suporte a re-criptografia

### Sem Sincronização na Nuvem
- ℹ️ E09.5 persiste apenas em Downloads/SharedPreferences
- ℹ️ **Recomendação E10+:** GoogleDrive ou Dropbox sync com criptografia E2E

### Sem 2FA / Biometria
- ℹ️ E09.5 usa senha de texto simples (prompt)
- ℹ️ **Recomendação E10+:** Integrar BiometricPrompt + TOTP

### Sem Backup Incremental
- ℹ️ E09.5 exporta snapshot completo (não delta)
- ℹ️ **Recomendação E10+:** Implementar diff-based backups
